# ESP32-S3 脱离电脑联网问答调研

日期：2026-10-20。代码依据：`870758dd03ac3b5433fb1cc79127001db7e62a00`，固件 1.36。本文是调研与建议，**没有给设备安装 Wi-Fi 功能，没有刷写本轮构建，也没有调用付费模型服务**。

## 结论

现有 ESP32-S3 N16R8 可以作为独立联网语音终端：插 USB 电源，接入 2.4 GHz Wi-Fi，查询天气，或把录音送到在线服务，再播放回答。不需要家用电脑一直开机。

但 Wi-Fi 只提供网络连接，不能替代语音识别、模型推理、搜索和语音合成。完整自由问答建议由在线服务承担重计算，ESP32 负责按键、录音、联网、喇叭和表情。在线服务可以在云端，也可以在另一台常开设备；若仍部署在当前电脑上，就没有满足“电脑关机也能用”。

仅查询固定城市天气可以由主控直接请求天气 API，不一定需要大模型或搜索引擎；“语音问一句天气”还需要识别这个意图，“自然地播出任意天气描述”还需要合成或组合语音。

## 最新仓库实际变化及评估

已执行 `git fetch origin main`，远端与本地代码基线一致，工作区起初干净。

- DeepSeek 把动画素材预先旋转为屏幕方向，播放时的调色改成连续读取，去掉旧的 168 字节列向跨步读取。
- 转场混合合入调色过程，相同像素跳过混合；保留 13 个动作、40 fps、220 ms 转场、6 MiB 无损变化缓存。
- 加入 CPU、PSRAM、内部 RAM、闪存、仅解码、仅调色和不同内存访问模式的串口诊断，模式 4–13 不向 LCD 写图。
- 仓库记载某些内存访问对比与闪烁相关；用户本次反馈这些优化仍没有明显解决问题。因此“列向读取与症状相关”不能升级成“已证实唯一根因并修复”。
- 60 fps 曾试验后回退：168×168×2 = 56,448 字节/整帧，60 fps 的整帧数据为 3,386,880 字节/秒；26.67 MHz SPI 的理论数据上限约 3,333,333 字节/秒，尚未扣命令和处理开销。差分可能减少平均传输量，但大范围动作或转场不能保证小矩形。保留 40 fps 有依据。

继续优化显示应先补足数据，而不是再随机提高帧率：记录实际变化矩形面积、传送字节/秒、计算及传屏的峰值耗时、内部/外部堆余量与分配失败，分别比较待机、转场、说话和以后 Wi-Fi 发送场景。保留离线预旋转；评估重复源帧的无变化跳过、缓存回收开销和单次传屏窗口，避免恢复曾有问题的碎片化绘制。单靠软件诊断仍不能测量电源或 BLK 的真实波形。

## 当前项目中缺少什么

检查 `voice-device/src/main.cpp`、`dsh_pet.h` 和 `platformio.ini`：当前固件没有 Wi-Fi 配网、HTTPS 天气请求、网络录音上传或云端对话客户端；按键语音链路仍依赖 USB。

当前分工是：

`麦克风 → ESP32 → USB → 电脑 Bridge → 识别/智能体/语音服务 → USB → 喇叭`

Whisper、CosyVoice/派蒙等桌面服务不会因为主控接上 Wi-Fi 就转移到芯片上；电脑关机后也不能继续调用电脑上的 Hermes/Harness、读取其本地文件或沿用其桌面进程。云端对话、会话保存和权限需要另行设计。

## 资源预算：必须先解决

| 项目 | 本次核对结果 | 对联网版本的影响 |
| --- | --- | --- |
| 硬件 | 已知 N16R8，16MB Flash、8MB PSRAM | 网络终端可行，但不是桌面模型运行环境 |
| 应用分区 | `0xFF0000` = 16,711,680 字节，单 factory app | 没有双应用 OTA 回滚空间，也没有独立语音模型分区 |
| 本次 1.36 编译 | Flash 使用 16,294,925 字节，约 97.5% | 约剩 416,755 字节（407 KiB）；增加网络/TLS 能否装下须实编译，不预先保证 |
| 动画包 | 15,764,072 字节，另有背景等资源 | Flash 的主要占用是动画；联网原型需要单独制定精简素材预算 |
| 运行时缓存 | 最大 6 MiB；原逻辑分配前预留 512 KiB PSRAM | 不能把这点余量默认视为足够容纳联网、TLS、音频和识别模型 |
| 音频 | 16 kHz × 16 bit × 单声道 | 原始 PCM 为 32,000 字节/秒；5 秒约 160 KB，适合分块发送而非长期整段堆积 |

建议联网原型先把可选动画缓存预算降至约 2 MiB，测量 TLS 握手、接收和播音时的实际峰值，再调整；2 MiB 是待验证的起始设计，不是已测最优值。先用小型保底表情或少量预旋转动作证明网络链路，稳定后逐步恢复完整素材；现有 1.36 完整动画版本保留为可回退基线，不覆盖其唯一副本。

加入 ESP-SR 模型、双槽 OTA 或较大中文字体都需要额外 Flash 预算，不能仅靠修改应用分区标签“腾空间”。首个天气画面可先显示图标和温度数字，中文字体另计。

## 可选路径

| 路径 | 家用电脑能否关机 | 适用范围 | 主要代价 |
| --- | --- | --- | --- |
| Wi-Fi 连接现有电脑 Bridge | 不能 | 先去掉 USB 数据线，复用所有本地功能 | 仍依赖电脑，不满足最终要求 |
| ESP32 直接调天气 API | 可以 | 固定地点天气、时间、简单状态 | 语音输入和播报还需补齐；不等于自由问答 |
| ESP32 直接调用云 ASR/模型/搜索/TTS | 可以 | 通用联网语音问答 | 多套协议、鉴权、流式音频和密钥维护较复杂 |
| ESP32 连接云端语音网关（推荐） | 可以 | 自由问答、天气、搜索、统一会话管理 | 需要云端常在线服务及相应 API/托管预算 |

推荐链路：

`按键录音 → ESP32 Wi-Fi/WSS → 在线网关 → ASR → 天气工具或搜索 + 模型 → TTS → ESP32 喇叭`

对于只是查天气的请求，直接调用天气工具，避免让模型根据训练记忆猜实时天气。天气失败时明确报告失败，或标注上次缓存时间。

已有成熟参考 [小智 ESP32](https://github.com/78/xiaozhi-esp32)：其官方仓库包含 Wi-Fi 配网、ESP32-S3、网络语音传输和云端工具扩展。它证明这种终端架构已有实现，但不是当前接线/动画可以直接使用的成品固件。其当前主线要求 ESP-IDF 6.x，而本项目是 Arduino/PlatformIO 体系；应参考协议和模块，不直接把两套工程混装，也不盲刷其他板型固件。[协议参考](https://github.com/78/xiaozhi-esp32/blob/main/docs/websocket.md)。

## 天气、搜索和语音分别怎么做

### 天气

[Open-Meteo](https://open-meteo.com/en/docs) 提供经纬度查询和结构化 JSON。其[免费开放接口](https://open-meteo.com/en/pricing)供非商业用途使用，有限额、需要遵守归属说明，不保证可用性；不能把它描述成无限免费商业服务。

本轮用示例坐标（不是用户所在地）从 Windows 主机直连 HTTPS API，取得 HTTP 200、436 字节 JSON，并验证温度与天气代码字段。这只证明该主机当时能访问接口，**不是 ESP32 联网实测**，也不保证用户路由器到该接口的可达性。

设备没有已知 GPS 定位模块。首版应由手机配网页或管理页设置城市/经纬度；Wi-Fi 联网本身不会可靠地告诉它用户所在城市。建议缓存 10–15 分钟，展示时间和单位；“当前”字段通常是天气模型数据，不应保证为附近气象站实时观测。

### 搜索

[DeepSeek 官方 Search/Fetch 文档](https://api-docs.deepseek.com/guides/search/)现已提供搜索和页面读取 API；需要 API 鉴权，有独立计费规则。文档还说明 [Responses API 的内建 web_search](https://api-docs.deepseek.com/guides/responses_api/#tools)对 `deepseek-v4-pro` 有支持，而不是所有模型都支持。实现前须验证实际账号、所选模型及是否经过第三方兼容接口。

另一种方式是由网关显式调用搜索，再把限长结果交给模型总结。这个方式可以统一天气工具和搜索来源，保留出处、抓取时间和请求预算。模型输出工具调用时，必须实际执行工具并回传结果；不能把工具名或一句“我查到了”当成完成检索。

不建议让微控制器承担通用浏览器：复杂网页的脚本、验证码、大体积内容和抽取应由搜索/抓取服务处理，主控只收取经过限制的结果或语音。

### 语音

[ESP-SR MultiNet](https://docs.espressif.com/projects/esp-sr/en/latest/esp32s3/speech_command_recognition/README.html)适合预定义命令识别，可将“查天气”作为有限命令方案评估；它不等于当前桌面 Whisper 的任意中文听写。部署模型和声学前端仍需额外分区及内存。具体支持命令数量以选定版本为准，不按不同文档的上限混用。

自由中文提问建议先使用在线 ASR；ASR、模型推理、搜索、TTS 是不同能力，不能假定一个 DeepSeek 文本 API 已包办全部。可选服务包括 [Paraformer 流式识别](https://help.aliyun.com/zh/model-studio/paraformer-real-time-speech-recognition-python-sdk)和 [CosyVoice](https://help.aliyun.com/zh/model-studio/cosyvoice-large-model-for-speech-synthesis/)，这是接口能力示例，不是已替用户购买或启用。试用额度与后续费用需要另查账号。

现有免费桌面音色可以保留在 USB/电脑模式；若要电脑关机后仍用同一套模型，需要在别处部署它及承担计算资源，不能称为纯主控本地免费运行。低成本天气播报也可研究预录数字/短语组合，但只能覆盖有限表达，不能替代任意回复的 TTS。

## 建议实施顺序与验收

1. **资源与传输分层。** 保留 1.36 基线，提出网络原型的 Flash/PSRAM 预算；录音、播音、表情与 USB/Wi-Fi 传输解耦，不在 LCD 任务中做网络请求。网络代码在 `voice-device/src/network/` 下独立组织；如选网关则另建 `services/robot-gateway/`，均为计划中的目录。
2. **主控直连天气原型。** 配网、SNTP 校时、HTTPS 证书验证、固定城市和 JSON 显示。先用按键触发查询证明不依赖电脑，明确这还不是“听懂一句自然语言”。验收须在电脑关机、仅 USB 电源供电下重复成功，并覆盖 Wi-Fi 断开、超时、无效响应和恢复。
3. **独立语音闭环。** 保留按键触发，分块录音上传、在线识别和回复、分块播音；中止旧回复后丢弃旧任务数据。验收 10 轮中文提问、网络中断恢复、连续播放和表情并行，无设备重启或持续音频欠载。
4. **天气工具与通用搜索。** 分开路由并保留来源/数据时间。断网时继续本地动画，不编造天气或搜索结果；用户可区分缓存内容。
5. **管理页和桌面兼容。** 网关保存会话，手机管理不依赖当前电脑服务；电脑 Bridge 继续作为可选控制入口。当前桌面 Hermes/Harness 会话不会自动迁移成云端常驻智能体，需要单独迁移设计。

延迟目前没有设备联网测量，不承诺固定几秒出声。阶段性记录连接耗时、首个识别结果、首个模型字、首段 TTS、音频缓冲低水位和帧率峰值，而不只看平均帧率。

## 安全、费用与闪烁风险

- 主控通过出站 HTTPS/WSS 连接服务即可，不需要开放家庭公网端口。按 [ESP HTTP Client](https://docs.espressif.com/projects/esp-idf/en/latest/esp32s3/api-reference/protocols/esp_http_client.html)文档配置证书验证，不用跳过验证来掩盖时间或证书错误。
- Wi-Fi 密码和服务密钥不进入公开 GitHub。网关方案建议主控只持可撤销的单设备令牌，服务商主密钥留在服务器，并设置限额。
- 个人天气原型可以使用免费开放数据；通用 ASR/模型/搜索/TTS 与网关托管不保证永久免费。无需家用电脑与完全不依赖在线服务是两种不同目标。
- [乐鑫硬件设计指南](https://docs.espressif.com/projects/esp-hardware-design-guidelines/en/latest/esp32s3/schematic-checklist.html#power-supply)强调供电余量与去耦。联网尤其发送时可能改变电流负载；现有未解决的闪烁有可能受影响，不能假定换成 Wi-Fi 会改善它，也不能在未测量时认定欠压。
