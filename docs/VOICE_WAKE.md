# 语音唤醒：你好，大肥鱼（1.62 双麦版，听感验收待完成）

## 使用与边界

在 Bridge 的显示/语音弹出面板开启“语音唤醒”。先说“你好，大肥鱼”，机器人以当前形象绑定的声线回应“在呢”，等它说完并出现录音表情后再提问；结束后安静约 1 秒，问题发送给当前网页选中的 AI 和会话，沿用绑定声线朗读回复。唤醒使用本地 Vosk 中文模型，问题正文仍用 Whisper。电脑和 Bridge 需运行；Wi-Fi 启动问题未解决，当前通过 USB 工作。

唤醒提示是本地固定短句，不向 AI 发送消息；启动和切换角色后后台预生成“在呢。”，按声线在内存及私有 `cache/wake-cues/` 缓存，不保存用户背景录音。修剪模型输出的长空白并保留字头/尾音；重启优先读取缓存。提示期间丢弃待机音频，等音频包确认且发送 AUDIO_END 后安静约 0.3 秒才请求正式录音；不再额外等待最长 3 秒的旧 STATUS。全局静音/零音量时跳过提示，仍可开始录音。关闭唤醒、断连或手动开始录音会取消尚未完成的自动流程；提示合成/播放失败会返回待命并显示错误，不悄悄开启麦克风。

完整唤醒词的普通 PartialResult 连续稳定约 300 毫秒时可提前触发，不再只等最终句尾。最终结果仍要求平均置信度不低于 0.75；完整词以外的部分匹配不会触发。普通 partial 不带逐词置信度，因此实际环境的误唤醒率仍需真人测试。Whisper 在 Bridge 启动时本地预加载；球球长回答先按完整短分句合成首段，再处理余文，短中英混合句保持完整。

默认关闭。开启后，主控向电脑本地识别器发送待机 PCM，背景音频不写文件、不上传云端。队列至多 64 包，超过约 0.6 秒的积压会丢弃。用户正式提问才进入原会话流程。唤醒后 6 秒没有足够语音会取消，录音最长 20 秒，有语音后连续静音约 1 秒提交；阈值待真人测试调整。按键录音仍手动结束。

播音时固件暂停待机音频上传；Bridge 识别正文、等待 AI、播音时也暂停唤醒。此版不支持语音打断播音或声学回声消除，物理按键原有功能保留。后台识别抑制及合成对照不替代真人误唤醒率测试。

## 回复播放规则

- 按键录音、唤醒后录音：问题按 `input_method=voice` 记录，当前轮 AI 回复自动使用机器人喇叭播放。
- 手机或电脑网页打字：按 `input_method=text` 记录，回复只显示文字，不自动播音；仍可点击消息旁的播放按钮手动朗读。
- 打字任务后来用语音确认审批，仍保留最初的文字输入规则，不自动朗读最终回复。Hermes 与 DeepSeek Harness 使用同一规则。
- 全局静音和零音量继续生效，恢复声音不会补播以前的回复。

## 双 INMP441 接线与处理

用户已连接两只 INMP441，固定为前后间距约 5 厘米、拾音孔朝上。原来那只在后面，L/R 接 GND；新麦克风在前面，L/R 接 3V3。共用时钟、WS、SD，不能同时驱动同一声道。L/R 表示芯片 I²S 声道选择，驱动接收槽与实物前后映射仍可通过近讲对比核验。

| 引脚 | 主控连接 | 两只麦克风 |
|---|---|---|
| VDD | 3V3 | 共用，不能改接 5V |
| GND | 主控 GND | 共地 |
| SCK | GPIO4 | 共用 |
| WS | GPIO5 | 共用 |
| SD | GPIO6 | 共用 |
| L/R | 后麦 GND、前麦 3V3 | 不悬空 |

依据 [TDK 数据手册](https://product.tdk.com/system/files/dam/doc/product/sw_piezo/mic/mems-mic/data_sheet/inmp441.pdf) 第 8、11 页：L/R 低为左、高为右；非工作时段 SD 高阻，支持共线；芯片供电 1.8–3.3V。原厂推荐每只 0.1µF 去耦、SD 100kΩ 下拉，成品模块是否自带需要核对。

1.62 新增 `stereo_protocol=1`。Bridge 的“自动”选项显示为“双麦降噪（自动）”，通过 WAKE_CONFIG 的声道模式 3 协商双声道；24/25 帧分别上传正式录音和待机的 16kHz、PCM16 交错声道。旧固件继续使用原单声道协议，固定左/右选项保留原始单声道作为对照。

两路音频在电脑端处理：按 5 厘米间距限制候选延时在约 ±2.33 个采样内，待机估计对齐延时、正式录音保持；用延时合成及带下限的相干性后滤波抑制不相关背景声，减弱低频轰鸣。每次处理 8 毫秒，重叠相加带来约 8 毫秒起始延迟；某路信号缺失或幅度极低时退回较强的单路，不直接减掉两路声音。只在内存保留短窗口和统计，不保存待机录音。

这是保守的双麦算法首版，不是声纹识别或 AEC，没有指定“只听前方某个人”。同方向电视/旁人人声及相干噪声仍可能进入识别。原厂 [麦克风设计建议](https://docs.espressif.com/projects/esp-sr/en/latest/esp32/audio_front_end/Espressif_Microphone_Design_Guidelines.html) 给出双麦间距 4～6.5 厘米；实际效果需在当前外壳和声源位置实测。

唤醒后自动录音不再仅凭音量判断说话/静音，改用已安装 faster-whisper 携带的本地 Silero VAD v6 流式判断，无新增模型下载。风扇等非人声不应持续重置结束计时；电视人声仍会被视为人声。按键录音仍由用户手动结束。

- 166 项后端、19 项网页测试通过。覆盖抑制自唤醒、手动录音、静音提交、无语音取消、旧音频/控制丢弃、鉴权与持久化。
- Windows 合成对照：指定唤醒短句触发，普通天气问句不触发。
- 1.61 阶段：实物确认配置回执、持续待机 PCM、armed 状态及错误计数 0。真人测试触发一次唤醒并识别问题，但发送 Hermes 时遇到 Gateway 8642 未启动，随后已恢复本地服务；当时第二麦克风尚未连接。

### 1.62 双麦记录（2026-10-21）

- 186 项后端、19 项网页测试通过。新增验证：独立噪声衰减、对齐信号幅度和连续性、单麦回退、5 厘米延时范围、录音期间延时保持、旧固件兼容、畸形/断连音频丢弃、流式 VAD、强非人声不延长自动录音。
- 合成实验不代替实物效果：电脑 DSP 平均约 0.096 毫秒/8 毫秒输入；本地 SAPI 人声 191 帧中 122 帧被 VAD 判为人声，静音拒绝。纯独立噪声测试降低超过 3dB，不能据此声称房间电视或人声也降低相同数值。
- 固件 1.62 共 15,923,760 字节；先校验旧 1.61 备份，再差分写入 974,848 字节，整份新镜像 digest 匹配。备份和烧录临时文件在私有数据目录。
- Bridge 已恢复双声道模式 3，两路均有信号，实测约 16,039 个处理后采样/秒、CRC 错误 0。已观察到一次 acknowledging→recording→waiting_for_agent→speaking→sent_to_device，实际听感、噪声改善及漏字仍待用户反馈。动画、声线、音量、静音、手机文字不自动播音规则不变。
