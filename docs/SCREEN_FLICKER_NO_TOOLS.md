# 屏幕闪烁：现状与无仪表排查方案

更新：2026-10-19。当前固件：**voice-device-1.26**。

## 当前可用状态

- 主控通电即自动播放 DSH Pet 小女仆“屈膝行礼”，约 10 秒后过渡到待机，无需电脑或 Bridge 指令。用户已确认冷启动播放正常。
- Emotion Ball 保留为手动选项，默认主题为小女仆；Bridge 保存有效的手动主题选择。
- 录音、思考和说话有对应动作；实际工作状态可以打断开机行礼。
- 动画动作流畅、图像正常，但用户仍能看到明显闪烁。**没有修复完成，也没有测得具体电压故障。**

## 已做过的对比

| 对比 | 实际反馈或验证 | 可得结论与限制 |
| --- | --- | --- |
| 静止画面，停止计算与传屏 | 不闪、不晃眼 | 静止、低负载状态可稳定显示 |
| 同一静止画面，约 40 次/秒重复传送相同内容 | 不闪、不晃眼 | 相同内容的传输本身未复现当时症状，不代表所有 SPI/供电条件均无问题 |
| 同一静止画面，不传屏，仅恢复动画计算 | 明显闪烁；再次停算不闪，恢复计算又闪 | 症状与计算/内存等工作负载相关；不足以证明供电、电磁干扰或某个器件是根因 |
| 20/40 MHz SPI 对比 | 最后反馈基本差不多 | 未找到明确改善档位 |
| 断开功放与主控的全部六根连接 | 闪烁基本一样 | 未支持功放连接是该轮待机闪烁的主要触发因素 |
| BLK 经电阻上拉到 3V3 | 初次明显改善，恢复完整系统后仍闪，安静待机也闪 | 不是完整系统的解决方案；电阻用户回忆约 3 kΩ，未经测量确认 |
| 更换 USB 数据线 | 基本一样 | 换线未改善 |
| 更换电脑 USB 接口 | 用户随后要求改算法，未提供明确比较结论 | 不记为已经排除的因素 |
| 屏幕 VCC/GND 直连主控 3V3/GND | 用户多次确认已直连 | 不要反复要求改成已经采用的接法；线长和接触电阻未测量 |
| 1.24 减少彩色帧复制，热数据优先用内部 RAM | 画面正常、丝滑，仍闪 | 减少内存搬运未消除闪烁 |
| 1.25 无损解压结果缓存 | 缓存命中时解码约 0.3–0.4 ms，约 40 fps；用户反馈仍明显闪烁 | 实时解压明显减少，仍未解决亮度问题 |
| 1.26 自主开机动画 | 用户确认开机自动播放正常，但仍闪 | 开机功能通过，闪烁未通过 |
| 原 USB 线改接家用 USB 充电头，主控自主播放 | 用户反馈“上了家用电源还是不行” | 闪烁仍未解决。没有精确比较严重程度；同时移除了电脑 USB 数据连接，不能据此把所有电源/接地因素排除 |

## 已验证的软件与图像

- 当前图集 13 个动作，每个 402 帧，源时间轴 40 fps；随机待机动作结束后的间隔为 8–22 秒。
- 1.25 缓存负载上限 6 MiB，分配前检查至少 512 KiB PSRAM 余量；缓存失败时可正常解压回退。缓存减少重复解压，不消除所有内存或 CPU 负载。
- 设备帧指纹与电脑独立 zlib/XOR/调色/旋转解码的 28,224 个像素一致，包括缓存播放动作 0/帧 59。此验证针对软件缓冲，不是 LCD 实际电气输出的回读。
- 1.26 离线启动的动作 9 帧号持续推进并自动回到待机；USB READY 不截断行礼，LISTEN 可提前接管。诊断时未见 CRC 错误。
- 最近一次相关完整回归：146 项 Bridge 测试、11 项网页测试通过；固件编译和烧录扇区哈希验证通过。

## 接下来不用万用表或电容也能做的事

这些是候选下一步，不代表已实现或已执行。

### 1. 拆分软件负载，保留同一张静止画面

现有 `scripts/display_ab_test.py` 支持 `hold`、`repeat`、`compute-only` 和不同 SPI 时钟的正常动画。它必须独占串口，运行前释放 Bridge 的串口连接，退出恢复正常动画和 Bridge。默认十分钟超时；不要在测试中按录音键。

下一种更有区分度的固件诊断可增加：

| 场景 | 固定条件 | 新增工作 | 目的 |
| --- | --- | --- | --- |
| 静止基线 | 不写 LCD、不播声音 | 无动画计算 | 验证本轮基线是否稳定 |
| 内部运算负载 | 同一画面，不写 LCD、不访问动画图集 | 在内部 RAM/指令 RAM 上做有界运算 | 观察不依赖动画内容时是否复现 |
| 外部内存读写负载 | 同一画面，不写 LCD、不解压素材 | 对固定 PSRAM 缓冲作有界复制 | 与内部运算对照，观察内存访问相关性 |
| 原动画计算负载 | 同一画面，不写 LCD | 正常解码、调色、合成 | 重现既有 `compute-only` 结果 |

内部运算和 PSRAM 读写诊断**尚未加入 1.26**。PSRAM 复制也需要 CPU，不能称为“只有内存、没有 CPU”。需要记录负载占空比、时钟、计数、实际耗时和图像指纹；不同场景功耗无法在无仪表条件下严格匹配。结果只能缩小范围，不能直接判定电压或器件故障。

### 2. 布线位置对比

若线材允许，断 USB 后把屏幕信号线与电源、BLK 的长距离并行捆绑分开，并检查杜邦头是否插牢；针脚和供电电压保持原样。每次只改变一项，再观察同一段动作。不要带电拔插，也不要在未知模块原理图下把 BLK 直接短接到电源或地。

已有 VCC/GND 直连，不将“再直连一次”作为新测试。原始屏幕供电继续是主控 **3V3**。

### 3. 手机视频作为辅助记录

如果现有相机支持，可固定手机和位置、锁定曝光/对焦，分别记录静止低负载与静止计算负载，各几秒。画面中保留屏幕外的参照物和四角，观察是否只在屏幕上发生明暗变化。可比较不同录像帧率，但滚动快门、室内照明和自动曝光也会产生条纹或假象；单凭视频条纹不能判断电源纹波，更不能测量实际电压。

### 4. 按结果决定是否继续软件实验

- 如果内部运算或 PSRAM 读写也能使固定画面闪，继续查共享供电、地线、背光控制和干扰；不再把动画插帧当作根因修复。
- 如果这些负载都稳定而特定动画仍闪，再检查素材逐帧亮度、转场与屏幕写入过程。
- 如果这些对比仍不能区分，需要借用测量工具或用已知正常的同型号屏幕/主控交叉对比。无仪表条件下不能保证给出唯一根因，也不应把“未重启、CRC 0”当作屏幕电源正常的证据。
